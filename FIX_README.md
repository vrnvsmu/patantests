# TestPatan — исправления

## 360° (можно применить отдельно)
Замените index.html в GitHub. В приложенном SQL dump поле questions.block NOT NULL, а старый код передавал null при отсутствии темы. Теперь используется specific как технический блок, topic_id остаётся NULL, is_exam=true. При ошибке отображается этап и код. Если запись вопроса могла состояться, кадры сохраняются: проверьте черновик и набор в Neon перед повторной загрузкой. Загрузка/удаление S3 оставлены на существующем удалённом endpoint, который по сообщению пользователя работает. Не удаляйте этот удалённый endpoint, пока не замените механизм записи S3. Исходник старого обработчика отсутствует в архиве.

## Гости — требуется настройка сервера
Data API без JWT возвращает 401; SQL GRANT не исправляет проверку JWT на gateway. Новый functions/guest.ts — отдельный узкий HTTP API, не связан с S3. Его необходимо опубликовать в среде, поддерживающей данный fetch-handler и Node pg (например, в той же среде, где опубликован имеющийся helloworld, если она поддерживает pg). Фактический URL и способ деплоя из архива установить невозможно. Не публикуйте пустой GUEST_RPC_URL в production, если хотите рабочий гостевой режим.
1. В Neon SQL Editor, ветка test, после резервной копии выполните sql/0009_guest_api.sql (если ещё не применён), затем sql/0010_guest_role_hardening.sql. Не импортируйте повторно полный dump.
2. Создайте отдельную роль LOGIN с сильным паролем через SQL Editor (не используйте владельца БД). Например CREATE ROLE testpatan_guest_login LOGIN PASSWORD 'ЗАМЕНИТЬ_СЛУЧАЙНЫМ_ПАРОЛЕМ'; GRANT testpatan_guest_api TO testpatan_guest_login; GRANT CONNECT ON DATABASE neondb TO testpatan_guest_login;. Если роль уже есть, не создавайте повторно. Убедитесь, что у неё нет административных членств.
3. Опубликуйте functions/guest.ts как публичный HTTP endpoint (без обязательного JWT на gateway), задайте серверные переменные GUEST_DATABASE_URL (строка подключения новой роли к ветке test, sslmode=require), ALLOWED_ORIGIN=https://vrnvsmu.github.io. Не помещайте строку подключения в index.html. Проверьте POST {"name":"list_topics","args":{}}: должен вернуть data с темами. Если среда не поддерживает Node pg или публичный endpoint, потребуется другой runtime; один GitHub Pages не исполняет серверный код.
4. В index.html замените пустое значение GUEST_RPC_URL фактическим HTTPS URL опубликованного guest endpoint, затем загрузите index.html в GitHub.
5. Проверьте гостевые темы, экзамен, ответ, завершение, разбор, вход и статистику. Проверьте отказ при подстановке чужого guest token. Ограничьте частоту запросов на публичном gateway перед production.

## Ограничения
Локально проверен синтаксис JS. Реальная БД, SDK, деплой и браузерные интеграционные тесты не проверены. Старый GUEST_ACCESS_AUDIT.md описывает удалённый обработчик и не является актуальной инструкцией. Сохранение 360° пока состоит из нескольких запросов, поэтому при сбое могут остаться черновики; они не удаляются автоматически вместе с кадрами. Новый guest API требует отдельной настройки, это не готовый деплой.
