ТЕСТОВАЯ СБОРКА TestPatan → Neon (ветка test)

Файлы:
- index-neon-test.html — тестовый HTML на официальном @neondatabase/neon-js 0.9.0-beta; Neon Auth + Neon Data API.
- functions/timewebs3.ts — обновлённая Neon Function для 360°, изображений и новых файлов материалов в Timeweb S3.
- neon.ts / package.json — текущая конфигурация Neon Functions из проекта.

ВАЖНО: это тестовая сборка. Не загружайте её в основную ветку GitHub Pages и не заменяйте production index.html. Сначала проверьте локально.

1) Распакуйте архив в C:\Users\user\testpatan-neon. Не заменяйте .env.local, .neon и .gitignore.
2) Скопируйте functions\timewebs3.ts из архива поверх одноимённого файла в проекте.
   Скопируйте neon.ts из архива поверх текущего neon.ts (в нём уже включены auth: true и dataApi: true).
3) Откройте .env.local в Блокноте и измените только ALLOWED_ORIGIN на:
   ALLOWED_ORIGIN=https://vrnvsmu.github.io,http://localhost:8000
   Другие переменные и секреты не меняйте и никому не отправляйте.
4) В PowerShell из C:\Users\user\testpatan-neon выполните:
   neon deploy --env .env.local
   Должна обновиться функция timewebs3.
5) Скопируйте index-neon-test.html в корень папки проекта.
6) Запустите локальный сервер из этой папки:
   py -m http.server 8000
7) Откройте в браузере:
   http://localhost:8000/index-neon-test.html
   Остановить сервер: Ctrl+C в PowerShell.

Если Neon Auth сообщит invalid domain, в другой вкладке PowerShell из папки проекта выполните:
   neon neon-auth domain add http://localhost:8000

Проверка входа и старых аккаунтов:
- Пароли из Supabase не переносятся. Старый пароль не будет работать автоматически.
- Для переноса истории пользователь должен зарегистрироваться в тестовой версии с тем же логином (тот же email вида логин@testpatan-vgmu.com), но задать новый пароль. После входа приложение вызывает claim_legacy_account() и связывает старый профиль/историю/права администратора.
- Не создавайте тестовый аккаунт с другим логином, если нужно проверить перенос существующей учётной записи.

Хранилище:
- Новые загрузки изображений и кадров отправляются в Timeweb S3 через Neon Function. Новые документы материалов записываются в отдельный префикс neon/materials/.
- Старые изображения временно читаются с прежнего публичного Supabase Storage, если копия ещё отсутствует в Timeweb. Старые файлы материалов также временно открываются по старым публичным ссылкам. Поэтому Supabase пока нельзя отключать. Перенос старых объектов в S3 — отдельный этап.
- Серверная функция допускает только администратора Neon, проверяет JWT и ограничивает типы/размеры файлов.

Не публикуйте HTML в GitHub Pages, пока не проверены: гостевой режим, вход/регистрация, перенос старого аккаунта, профиль, все режимы теста, сохранение попытки, избранное, админка, загрузка/удаление изображения, 360° кадры и материалы.
