ТЕСТПАТАН ВГМУ — проект разработки

СОДЕРЖИМОЕ
- site/index-demo.html — увеличенная локальная демоверсия интерфейса. Она НЕ подключена к базе данных.
- supabase/migrations/0001_init.sql — стартовая схема БД, политики доступа, серверная проверка результата и таблица рейтинга.
- docs/ARCHITECTURE.md — как устроен проект и важные решения.

ВАЖНО
Это не готовый к публикации сайт. Это пакет для следующего этапа: в нём подготовлена основа базы данных и сохранена демоверсия интерфейса. Для полноценного запуска нужно подключить интерфейс к Supabase, сделать формы регистрации/входа и панель администратора, а затем проверить политики безопасности.

КАК БУДЕТ РАБОТАТЬ РЕГИСТРАЦИЯ БЕЗ ПОЧТЫ
Supabase Auth обычно использует email/телефон. Чтобы пользователь вводил только логин и пароль, можно на клиенте преобразовывать уникальный логин в технический внутренний идентификатор вида username@accounts.testpatan.invalid и отключить подтверждение email в Supabase. Это не реальная почта и письма не отправляются. Пароль хранит и проверяет Supabase Auth — сайт не должен хранить пароли в своей таблице. Нужно предусмотреть защиту от коллизий имён, ограничение частоты регистрации и восстановление доступа через администратора, поскольку email для восстановления нет.

ПРАВИЛА РЕЙТИНГА
В SQL подготовлен рейтинг по среднему проценту правильных ответов, показываемый после минимум 3 завершённых тестов. Это уменьшает влияние одной случайной попытки. При равенстве можно сортировать по суммарному числу правильных ответов и затем по числу попыток. Перед публичным запуском стоит добавить защиту от спама попытками и определить, включаются ли тренировочные режимы в рейтинг или только экзамен.

ПОРЯДОК ДАЛЬНЕЙШЕЙ РАБОТЫ
1. Создать новый Supabase-проект.
2. Выполнить SQL из supabase/migrations/0001_init.sql в SQL Editor.
3. Подключить фронтенд к URL проекта и anon key (никогда не размещать service_role key в браузере).
4. Реализовать регистрационный flow с техническим email, профиль/аватар, публикацию вопросов и админ-панель.
5. Проверить RLS и тесты безопасности на отдельном тестовом проекте.
6. Опубликовать фронтенд на статическом хостинге.

Не запускайте SQL из этого файла поверх старой/рабочей базы без предварительной проверки.


Обновление гостевого режима: выполните SQL из supabase/migrations/0005_guest_test_solving.sql в SQL Editor проекта Supabase и загрузите обновлённый site/index.html на хостинг. Гости решают тесты без регистрации; статистика и рейтинг доступны только зарегистрированным пользователям.
