# TestPatan — исправление гостевого режима (полный патч)

Патч подготовлен на основе загруженного архива репозитория TestPatan от 26.11.2026.

## Что было не так

1. `init()` загружал `topics` напрямую через Neon Data API (`sb.from('topics')`). Для гостя этот запрос отклонялся из-за отсутствия JWT, поэтому папки оставались пустыми.
2. В исходном `index.html` запуск теста, проверка ответа и завершение попытки шли напрямую через `sb.rpc`, то есть обходили гостевой серверный шлюз.
3. В исходном `functions/timewebs3.ts` не было маршрута `/guest-rpc`: каждый запрос сначала попадал под `requireAdmin()`. Поэтому попытка использовать этот endpoint без сессии закономерно возвращала «Требуется вход в аккаунт».

## Состав

- `index.html` — гостевой вызов `list_topics`, а также гостевой маршрут для `start_attempt`, `check_answer`, `finish_attempt` и `get_attempt_review`. Авторизованный режим продолжает использовать Neon SDK.
- `functions/timewebs3.ts` — полный файл функции Timeweb S3 с отдельным allowlist-маршрутом `/guest-rpc`. Гостю разрешены только чтение публичного списка тем и операции с его анонимными попытками. Загрузка/удаление объектов S3 по-прежнему требуют входа администратора.
- `0008_guest_finish_attempt.sql` — NULL-safe завершение гостевой попытки (`user_id IS NULL`). Скрипт идемпотентный: использует `CREATE OR REPLACE FUNCTION`.

## Установка

1. В Neon SQL Editor выберите проект TestPatan, ветку `test`, базу `neondb`, выполните `0008_guest_finish_attempt.sql`.
2. Замените `functions/timewebs3.ts` целиком этим файлом и повторно разверните существующую функцию `timewebs3`.
3. Не удаляйте и не переименовывайте прежние переменные окружения функции. Нужны те же переменные, что используются текущей S3-функцией: `DATABASE_URL`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_JWKS_URL`, `TIMEWEB_S3_BUCKET`, `TIMEWEB_S3_ACCESS_KEY`, `TIMEWEB_S3_SECRET_KEY`, `ALLOWED_ORIGIN` и при необходимости `TIMEWEB_S3_ENDPOINT`, `TIMEWEB_S3_REGION`.
4. Замените корневой `index.html` в репозитории `vrnvsmu/patantests` и опубликуйте GitHub Pages.
5. Откройте сайт в приватном окне или очистите данные сайта, чтобы исключить старый HTML из кэша.

Новые секреты и переменные окружения не добавляются. URL гостевого маршрута в `index.html` использует тот же адрес функции `timewebs3`, который уже присутствует в загруженном репозитории.

## Проверка

В приватном окне проверьте по порядку:

1. При открытии сайта загрузились названия тем и количество тем в папках.
2. Откройте папку «Общая» или «Частная» в режиме «Макро», «Микро» или «Теория».
3. Запустите тему и ответьте на вопрос: должна появиться обратная связь «Верно/Неверно».
4. Откройте «Экзамен», ответьте на несколько вопросов и завершите попытку: должен появиться результат и разбор.
5. Повторите проверку после входа в аккаунт — авторизованный путь не должен измениться.
6. Проверьте администраторскую загрузку/удаление S3-файлов — эти операции должны по-прежнему требовать входа администратора.

## Границы гостевого режима

Гостевые попытки создаются с `user_id IS NULL`, ответы проверяются только для такой попытки, а состояние прохождения хранится локально в браузере. Гостям не открываются таблицы профилей, избранного, статистики, комментариев и административные операции. Личные результаты не синхронизируются между устройствами.

Патч проверен на синтаксис JavaScript (`node --check` для inline-скриптов) и TypeScript (`node --experimental-strip-types --check functions/timewebs3.ts`). Развёртывание в Neon и интеграционный тест с удалённой базой из этой среды не выполнялись.
