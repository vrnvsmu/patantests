# Архитектура «ТестПатан ВГМУ»

## Требования
- Студенческая регистрация: логин + пароль, никнейм, необязательная аватарка.
- Без привязки к настоящей электронной почте, соцсетям или телефону.
- Четыре режима: Макро, Микро, Теория, Экзамен.
- Вопросы сгруппированы по общей/частной патологии и темам.
- Только администратор публикует и редактирует контент.
- Рейтинг студентов.

## Модель данных
- `profiles`: логин, отображаемый ник, аватар.
- `topics`: учебные темы.
- `questions`: текст вопроса, раздел, тема, изображение, публикация, признак экзамена.
- `question_options`: варианты ответов без признака правильности.
- `question_answers`: ключи ответов; доступ только администратору.
- `attempts` и `attempt_answers`: результаты, рассчитанные сервером.
- `admins`: пользователи с административными правами.
- `leaderboard`: агрегированный рейтинг. По умолчанию в рейтинг попадают профили минимум с тремя попытками.

## Важные ограничения
1. Пароли не сохраняются в `profiles`; их хранит Supabase Auth.
2. В клиент нельзя помещать service-role ключ.
3. Ключ правильного ответа отделён от публичных вариантов.
4. Подсчёт результата выполняется серверной функцией `submit_attempt`, а не принимается на веру от браузера.
5. Технический email для логина — обходной путь для username/password в Supabase Auth; это не почтовый адрес пользователя. При отключённом подтверждении email пользователь сможет зарегистрироваться без письма. Потерянный пароль нельзя восстановить обычным письмом, поэтому нужно заранее определить безопасную процедуру восстановления.
6. SQL — стартовый каркас, который требует тестирования в отдельном проекте перед реальным использованием. Нужны дополнительные проверки: повторяющиеся вопросы в одной попытке, лимит запросов, транзакционное поведение и политика рейтинга.
