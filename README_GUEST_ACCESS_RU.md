# TestPatan — гостевой режим через Neon Function

Патч устраняет `AuthRequiredError` при запуске и решении обычных заданий без входа в аккаунт.

## Что меняется

- `index.html`: гостевые `start_attempt`, `check_answer`, `finish_attempt` и `get_attempt_review` идут через серверный endpoint `/guest-rpc`. Обычные авторизованные запросы остаются через Neon SDK.
- `functions/timewebs3.ts`: добавлен отдельный маршрут `/guest-rpc`. Он принимает только пять заранее разрешённых операций, валидирует аргументы и выполняет существующие SQL-функции через серверное подключение PostgreSQL. Остальные маршруты Timeweb S3 по-прежнему требуют администратора.
- `0008_guest_finish_attempt.sql`: исправляет `finish_attempt`, чтобы функция могла завершать попытки с `user_id IS NULL` (гостевые), сохраняя проверку владельца для вошедших пользователей.

Гостю не выдаются JWT, `DATABASE_URL`, права на произвольный SQL или административный доступ. Идентификаторы попыток UUID; `check_answer` и `get_attempt_review` дополнительно проверяют, что попытка гостевая. В серверной функции действует best-effort ограничение частоты запросов по IP, если платформа передаёт IP в заголовках.

## Установка

1. В Neon Console откройте SQL Editor именно для проекта TestPatan и ветки `test`.
2. Выполните файл `0008_guest_finish_attempt.sql` один раз.
3. Замените исходный `functions/timewebs3.ts` файлом из архива.
4. Повторно разверните существующую Neon Function `timewebs3` (не создавайте новую). Переменные окружения должны остаться прежними: `DATABASE_URL`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_JWKS_URL`, `TIMEWEB_S3_BUCKET`, `TIMEWEB_S3_ACCESS_KEY`, `TIMEWEB_S3_SECRET_KEY`, `ALLOWED_ORIGIN` и, при необходимости, `TIMEWEB_S3_ENDPOINT` / `TIMEWEB_S3_REGION`.
5. Замените корневой `index.html` файлом из архива и опубликуйте GitHub Pages.

Новый секрет или новая переменная окружения для гостевого маршрута не требуются.

## Проверка

Откройте сайт в приватном окне, где нет сессии:

1. Запустите задание в режимах «Макро», «Микро», «Теория» или «Экзамен».
2. Выберите ответ. Должна появиться обратная связь «Верно/Неверно» без `AuthRequiredError`.
3. Завершите тест. Должна открыться страница результата с разбором.
4. Повторите тест после входа в аккаунт: авторизованный путь должен работать как раньше.
5. Проверьте загрузку и удаление материалов администратором: они по-прежнему требуют валидную сессию и права администратора.

## Ограничения гостевого режима

- Избранное, личная статистика, профиль и синхронизация попыток между устройствами остаются функциями аккаунта.
- Состояние гостевой попытки записывается в `localStorage` этого браузера во время решения. Гостевые попытки не появляются в профиле и не синхронизируются между устройствами; отдельный список восстановления гостевых попыток этим патчем не добавляется.
- Rate limit в памяти Neon Function — дополнительная защита, а не полноценная антибот-система. Для публичного массового использования стоит добавить Cloudflare Turnstile или постоянный лимит в БД на основе доверенного IP-заголовка.
